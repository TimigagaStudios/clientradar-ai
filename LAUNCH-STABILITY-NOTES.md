# Launch stability batch

Base: main f06d7ac65a480b8c8f1eaf85e229fb3cee832314. Apply every path in this package in one review branch. No migration, new service, secret or production write is included.

## Changes

- Lead list and detail no longer fabricate AI-labeled star ratings when a rating is missing. An unknown rating contributes zero reputation points to the locally calculated fallback score; existing saved scores and ratings are unchanged. The detail summary now presents saved information as unverified, does not infer buying intent or the absence of a website, and does not invent a turnaround, outcome or price. A saved score may differ from the current local breakdown.
- Dashboard and Analytics sum saved values only on leads marked Deal Closed; labels explicitly distinguish saved values from payments. Deals and Tracker use the same closed-value calculation. Existing saved amounts may include old estimates: review them; this package does not establish which were paid. Tracker no longer compares all-time closed values against one year of costs and calls the result profit. There is no payment ledger or trustworthy profit calculation here.
- A closed lead with no saved amount no longer has a computed estimate prefilled into the actual-amount field or shown as its closed amount. The owner can enter an actual agreed amount; saved values are not proof of payment. Existing data is not changed.
- Dashboard removes fixed percentage trends and avoids counting a default Not Started demo status as a tracked demo. Email-stage figures are current saved statuses, not an independent count of delivery events.
- Lead Finder's website checks use the existing bounded DNS-pinned transport instead of unrestricted fetch and redirects. It rejects unsafe/private destinations, credentials and unusual ports, strips queries and follows only approved same-site redirects. The check remains a limited heuristic, not a security or visual audit. Legitimate sites may not be checked due to compression, large responses, IPv6-only hosts, cross-domain redirects or other constraints; unreadable is not proof of a good or bad website. A missing viewport tag is reported as a detected tag issue, not proof that the site is unusable.

## Verification and limitations

26 offline suites passed with simulated network sockets and providers, including private-address and redirect tests for the Lead Finder website-check path. Targeted server TypeScript checks passed; client diagnostics match 17 pre-existing errors after ignoring line-number shifts. Mocked actual-component Chromium and WebKit checks passed at 320, 390, 768 and 1280 for Dashboard, Analytics, Deals, Tracker, Leads and a closed Lead Detail: totals, no invented displayed rating, a blank missing closed amount, no fake trend, tracked demo count and page errors. These are not physical-device, live database, full integration, deliverability or full security tests. No real website, demo, provider request, customer email or production data was accessed for this test.

The prior lead-priority PR was merged and Vercel reported production deployment success. This new batch was bundled for the mocked browser fixture, but its production Vite build has not been verified locally; require a successful Vercel build for this branch and check the production UI after deployment. A healthy deployment does not prove client-work readiness. Pricing by industry and fully tailored demos remain for the owner's decisions. No claim is made that all existing provider usage is free. Demo creation, QA override and send approval gates remain separate and unchanged.
